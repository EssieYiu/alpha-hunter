# Alpha Hunter 一期产品与技术方案

状态：早期需求草案；当前仓库已有本地交互原型。后续新增图表、会话历史与策略管理功能，以及正式技术建议，见 [技术选型](technical-selection.md)。

## 1. 产品目标

围绕「查看指数 → 加入自选 → 理解信号 → 记录交易 → 跟踪持仓 → 回测验证」建立闭环。Agent 使用与页面一致的数据和策略接口，提供有依据的解释。

默认建议：中文 Web 应用，本地运行、单用户、日线策略、模拟交易及手工记账。真实券商交易是单独能力，需要订单状态同步、鉴权、对账与市场规则支持，不能用修改持仓代替真实成交。

## 2. 五个模块

### 行情与指数详情

- A 股候选：上证指数、深证成指、沪深 300、上证 50、中证 500、中证 1000、创业板指、科创 50。
- 港股候选：恒生指数、恒生科技指数、恒生中国企业指数。
- 美股候选：标普 500、纳斯达克综合指数、纳斯达克 100、道琼斯工业平均指数。
- 展示最新可得点位、涨跌幅、行情时间、来源、市场状态；历史日线支持日期范围、折线或 K 线、成交量（数据源支持时）。
- 区分最新快照和已收盘日线。明确数据延迟；接口失败显示错误或带时间的缓存，不用模拟数据替代真实行情。
- 指数标识使用内部稳定 ID，市场代码、供应商代码分开映射，避免跨市场重名。

### 自选与信号

- 添加和移除自选指数，查看趋势、风险、策略状态与信号变更。
- 第一个策略采用日线双均线，默认短期 20、长期 60，可配置。短均线上穿长均线为入场事件，下穿为离场事件；没有新交叉时展示持有或观望状态。
- 只使用已完成交易日的数据；区分「当日新事件」与「当前策略持仓状态」。数据不足、过期或缺失时返回不可判断。
- 返回规则版本、参数、依据数值、数据截止时间、触发理由及风险信息。结论表述为「策略入场／离场条件满足」，不声称可确定预测收益。
- 页面、Agent、回测调用同一个确定性策略服务。

### 持仓与交易

- 指数作为研究标的；实际记账对象是关联的 ETF／基金等产品。指数理论组合与产品持仓分别标注，不能把指数点位当作基金成交价格。
- 支持录入期初持仓、买入、卖出、手续费及现金变动，显示成本、已实现盈亏和浮动盈亏。
- 首期模拟交易可让用户填写成交日期、数量和价格，明确是手工记账，不宣称以实时行情自动成交。
- 持仓更正生成调整流水，保留历史依据；卖出数量不得超过可用持仓，金额和数量不得为负。
- 买卖、现金、持仓变更在同一数据库事务中完成；幂等键防止重复提交。
- CNY、HKD、USD 分币种核算；没有有效汇率时不显示跨币种合计。
- 如加入 ETF 自动撮合，需要增加对应产品行情、市场交易日历、最小交易单位、可卖规则、汇率及费用模型。

### Agent 聊天

- 将用户所说的 react 暂理解为 ReAct（模型选择工具、执行工具、根据结果继续回答），与前端 React 区分。
- 设置模型服务地址、模型名称与 API key；第一版适配支持 tool calling 的 OpenAI 兼容协议，不承诺所有兼容服务都支持工具。
- 默认 API key 仅存在当前会话内存，由后端代理请求，不进日志、数据库或浏览器持久存储。持久保存以后以显式选择和加密存储实现。
- 支持查询指数列表、最新行情、历史行情、自选、持仓、策略信号及运行回测。
- 工具调用参数由后端校验；限制日期范围、结果条数、调用轮数、超时及回测规模。
- 展示工具调用结果摘要与数据时间。工具失败必须明确说明，不能编造数据；不展示内部思维链。
- Agent 一期只有只读业务工具及回测工具；交易由用户在交易表单中提交。
- 用户输入的模型地址需要协议与目标地址校验，防止后端被用于访问任意内网资源；本地模型作为明确配置的单独模式。
- 外部模型仅接收完成问题所需的数据；发送持仓等个人信息前在设置中说明数据用途。

### 回测

- 选择指数、日期、策略参数、初始资金、手续费和滑点。
- 首期为指数价格序列上的理论策略回测；结果不等同于 ETF／基金可实现收益。
- 收盘生成信号，下一交易日开盘执行。开始日期以前的数据只用于指标预热；缺少预热数据时明确拒绝或提示有效开始日。
- 末日信号不虚构下一日成交；期末未平仓按收盘估值，报告未实现盈亏。
- 输出净值曲线、同区间买入持有基准、累计收益、年化收益、最大回撤、成交记录及已平仓交易胜率；交易数不足时不生成无意义胜率。
- 基准与策略使用相同起始资金、价格口径和费用约定；年化与无风险利率约定显示在结果中。
- 保存数据快照标识、策略版本与参数，使同一回测可复现。

## 3. 推荐架构

前端：React + TypeScript，行情图表与业务表单分模块组织。

后端：Python + FastAPI。Python 便于接入行情适配器、计算指标和进行回测。早期采用模块化单体，共享领域服务，不必先拆微服务。

数据库：早期曾建议本地 SQLite；基于新增后台任务和持久化需求，2026-09-12 技术选型建议正式版本直接采用 PostgreSQL，详见技术选型文档。

核心模块：market（行情）、watchlist（自选）、strategy（信号）、portfolio（记账）、backtest（回测）、agent（工具编排）。页面与 Agent 均调用这些模块的服务，避免重复实现规则。

行情：以可替换 Provider 接口隔离外部供应商。AKShare 作为研究原型候选，逐市场验证历史和快照覆盖；正式数据源选型依赖频率、预算、授权和稳定性需求。使用缓存、限流、超时和重试，保存 source/as_of/fetched_at/is_stale 元数据。

## 4. 主要数据实体

| 实体 | 主要内容 |
| --- | --- |
| indices | 内部 ID、名称、市场、时区、供应商映射 |
| instruments | 可交易产品、币种、类型、关联指数 |
| daily_bars / quotes | 历史与快照、来源、行情时间、采集时间 |
| watchlists | 用户与指数关系 |
| accounts | 模拟账户及币种 |
| ledger_entries | 买卖、期初录入、调整、费用、现金流水、幂等键 |
| positions | 由流水推导或在同一事务中维护的持仓投影 |
| strategy_configs / signals | 策略版本、参数、数据截止时间、事件与状态 |
| backtest_runs | 参数、数据快照、指标、净值及成交记录 |

金额使用 Decimal 或最小货币单位，时间保存 UTC 并按市场时区显示。数据库文件、凭证与本地运行数据不进入 Git。

## 5. API 初稿

| 方法与路径 | 功能 |
| --- | --- |
| GET /api/indices | 支持的指数目录 |
| GET /api/indices/{id}/quote | 最新可得行情及新鲜度 |
| GET /api/indices/{id}/history | 日期范围内历史日线 |
| GET /api/watchlist | 自选列表 |
| PUT /api/watchlist/{id} | 幂等添加自选 |
| DELETE /api/watchlist/{id} | 删除自选 |
| GET /api/indices/{id}/signal | 策略状态及触发证据 |
| GET /api/portfolio | 分币种现金、持仓及盈亏 |
| GET /api/ledger | 交易及调整流水 |
| POST /api/trades | 提交模拟买卖记账 |
| POST /api/position-adjustments | 期初录入或持仓更正 |
| POST /api/backtests | 运行并保存回测 |
| GET /api/backtests/{id} | 查询回测结果 |
| POST /api/agent/chat | 有界工具调用及聊天 |

## 6. 分阶段验收

1. 行情底座：三个市场各验证一个指数的真实历史数据与快照；来源与截止时间可见；断网时明确显示过期缓存或错误。
2. 自选与信号：自选重启保留，交叉信号与手算样例一致，未收盘数据不会产生正式日线信号。
3. 持仓记账：买入、部分卖出、费用、现金及成本计算正确；重复提交不重复成交；超额卖出完整回滚；重启后数据保留。
4. 回测：验证下一开盘成交、费用、预热、最大回撤、末日信号及无交易情形；相同快照和参数结果一致。
5. Agent：实际调用工具回答行情与持仓问题；错误和超时可恢复；未配置模型时给出设置入口；密钥不出现在日志中。
6. 整体交付：运行说明、配置示例、数据库初始化及迁移、核心领域测试、页面交互验证。
